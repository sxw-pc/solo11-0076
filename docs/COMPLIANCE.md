# 离线、只读与合规边界

本文档说明 `topoaudit` 的数据边界、离线保证、输入保护、服务安全限制和操作者责任。它是工程事实说明，不构成法律意见或任何监管认证。

## 1. 授权使用前提

`topoaudit` 面向以下场景：

- 用户对自己拥有、已获授权或依法可以处理的本地矢量数据做质量检查；
- 在受控终端上运行，输出目录和台账由用户自行保护；
- 合成 fixture、开发和测试环境；
- 防御性数据质量验证、离线审计和审计留痕。

不应将本工具用于：

- 未经授权读取、汇总或披露他人数据；
- 将本工具包装成公网多用户服务；
- 以审计报告代替法定测绘、权属、规划、隐私或行业合规结论；
- 规避访问控制、数据授权或组织安全策略。

## 2. 完全离线运行

### 2.1 运行时无外部网络依赖

- 生产代码只使用 Python 标准库，不依赖第三方运行时包。
- 不导入 HTTP 客户端库访问远程 API，不连接云数据库、消息队列、对象存储或 GIS 服务。
- 没有遥测、崩溃上报、自动更新、许可证服务器或远程配置。
- Markdown 报告不含网络资源引用；HTML 报告和复核页面使用内联 CSS，不含脚本、外部样式、字体、图片或 iframe。
- HTML 报告包含 CSP `default-src 'none'`；服务响应还包含 `nosniff`、`no-referrer`、`no-store`、`frame-ancestors 'none'`。

### 2.2 唯一监听的网络端点

`serve` 只允许：

```text
127.0.0.1
localhost
```

默认端口 `8765`。任何其他主机名或地址（包括 `0.0.0.0`、局域网 IP、IPv6 通配地址）都会被拒绝，产生 `TOPO-SRV-001`。这是启动前的白名单检查，不是防火墙。

服务用于本机复核，不是对外服务，也没有 TLS。不要把端口转发、反向代理或隧道指向该服务。

## 3. 输入只读与输出保护

### 3.1 输入读取

- GeoJSON/CSV 通过 `read_bytes()` 读取，随后仅在内存中解码、解析和审计。
- 不打开输入文件进行写入、截断、重命名、删除或移动。
- 不把规范化结果回写到源文件。
- 不在输入文件旁自动生成 sidecar 文件。
- 不自动修复、合并、裁剪或重新投影数据。

### 3.2 输出冲突保护

`run` 和 `demo` 在写报告前会解析所有固定输出目标，并与以下路径比较：

- 配置文件自身；
- 每个图层的解析后输入文件路径。

若任一输出目标与配置/输入文件冲突，抛出 `TOPO-RPT-004`，不写入报告，避免 `report.json` 等固定文件名覆盖同名输入。

`demo` 还额外拒绝把输出目录设为 `fixtures/demo` 或置于其下（`TOPO-DEMO-001`），保证内置演示不会污染 fixture。

这些保护针对**固定输出文件名冲突**。`run` 的 `--out` 由操作者显式指定；如果操作者把输出目录指向其他数据目录，仍可能产生新的输出文件或更新同名旧报告。请把输出放在专用构建目录。

### 3.3 已有输出

- 同一输出目录中的 `report.json`、`report.md`、`report.html`、`inputs.json`、`summary.txt` 会被本次运行替换。
- `audit.sqlite` 是追加/幂等台账：相同 `result_digest` 不重复写入，新摘要新增运行。
- 输入文件哈希在运行前后保持不变；内置端到端测试对 fixture 做前后 SHA-256 比较。

## 4. 数据内容与敏感信息

### 4.1 报告可能包含数据摘录

报告和台账会包含：

- 图层 ID、要素 ID、属性字段名；
- 输入文件路径、格式、大小、SHA-256；
- finding 证据中的坐标、几何位置路径、属性值预览（最多 80 字符）；
- 运行标签和配置摘要。

因此，报告和台账本身可能包含敏感数据或可识别信息。应按与源数据同等级别保护输出目录、台账和屏幕展示。

### 4.2 仓库 fixture 为合成数据

- `fixtures/demo` 使用虚构 ID、合成几何和虚构的 `LOCAL_XY` 坐标。
- 不包含真实公司名、域名、邮箱、电话、地址、账号、令牌或密钥。
- 不使用真实地理坐标或可关联到真实人员的点位。
- 预期摘要只含计数和虚构标签。

操作者不应把真实凭据、个人数据或受限数据写入测试配置、`run_label`、fixture 文件名或源属性。工具不会自动识别或脱敏敏感字段；属性预览可能原样进入报告。

## 5. 本地复核服务的安全控制

服务实现只提供以下只读路由：

| 路由 | 内容 |
| --- | --- |
| `GET /healthz` | 健康状态和只读标志 |
| `GET /` | 台账中的运行列表 |
| `GET /rules` | 规则目录快照 |
| `GET /runs/<64位小写十六进制>` | 单次运行页面 |
| `GET /runs/<64位小写十六进制>/findings.json` | findings JSON，可过滤 |

控制措施：

- 只接受 `GET`/`HEAD`；`POST`、`PUT`、`PATCH`、`DELETE` 返回 `405` 和 `Allow: GET, HEAD`。
- 路由用固定正则匹配，不接受任意文件路径；没有目录浏览、静态文件服务、上传或下载接口。
- `result_digest` 必须是恰好 64 个小写十六进制字符。
- 查询参数只允许 `severity`、`layer`、`rule`，且每个最多出现一次；`severity` 只能是三个固定值。
- SQLite 查询使用参数绑定，不使用字符串拼接用户值。
- 复核连接以 `mode=ro` 打开，并启用 `PRAGMA query_only = ON`。
- HTML 输出对所有动态值做属性/文本转义。
- 服务不记录请求日志（覆盖了默认请求日志输出）。
- 页面的 CSP 禁止脚本、外部资源、表单提交和框架嵌入。

明确没有的控制：

- 没有认证、授权、会话、CSRF 令牌、TLS、速率限制或多租户隔离。
- 同一台机器上的其他进程可能访问回环端口，也可能直接读写台账文件；需要操作系统账户和文件权限保护。
- 本地恶意进程可对服务发起资源消耗型请求；该服务不面向敌对环境。
- CSP 和转义降低浏览器注入风险，但不构成完整的 Web 应用安全边界。

## 6. 台账完整性边界

- `result_digest` 是内容指纹，不是签名。
- `verify` 能发现单边修改、摘要不一致、明细与汇总矛盾等常见篡改。
- 如果攻击者同时控制报告和 SQLite，并能重算摘要，`verify` 无法证明来源真实性或时间真实性。
- 没有 HMAC 密钥、公钥签名、可信时间戳、远程见证或区块链存证。
- 需要强来源认证时，应在工具之外对报告/台账做签名，并保护密钥和审计日志。

台账使用 SQLite 标准文件。应依赖磁盘权限、备份、文件完整性监控和组织级日志来保护其机密性与可用性。

## 7. 配置和文件系统边界

配置文件是受信任的本地输入，不是沙箱脚本。它可以指定：

- 本地绝对路径；
- 含 `..` 的相对路径；
- 指向任意可读普通文件的路径。

因此：

- 只运行来自可信来源的配置；
- 在运行前审阅 `layers[].path`；
- 使用最小权限账户运行；
- 不要让不可信用户提交配置并在高权限环境中执行。

工具不会解析 URL、数据库 DSN 或远程 URI，也不会因为配置中的路径而主动发起网络连接。

## 8. 供应与运行环境

- 运行时依赖：Python 3.10+ 标准库。
- 不包含需要下载的模型、词典、瓦片、字体或数据库驱动。
- `pyproject.toml` 只声明打包元数据；源目录可直接用 `python -m topoaudit` 运行，不要求安装。
- 如组织需要可复现构建，应自行固定 Python 包构建工具版本和内部包源，并对构建产物做哈希。
- 不自动收集使用情况，不需要许可证激活，不访问远程时钟。

## 9. 明确排除的能力

以下能力不在本项目范围内，也不应通过修改配置获得：

- 地图渲染、瓦片、WebGIS 前端；
- CRS 转换、重投影、大地测量距离；
- 自动修复、写回源数据、批量合并；
- OGC/WFS/远程数据库/云存储连接；
- 栅格、三维、点云；
- 分布式任务调度、集群、消息队列；
- 用户登录、权限管理、公网发布、TLS 终止；
- 敏感字段自动识别、脱敏、加密或 DLP。

## 10. 操作者检查清单

- [ ] 已确认对输入数据拥有处理授权，并遵守数据分类要求。
- [ ] 已将 `--out` 指向专用输出目录，而不是源数据或 fixture 目录。
- [ ] 已审阅配置中的本地路径，没有远程 URI 或不可信路径。
- [ ] 未把凭据、真实个人数据或受限属性写入 fixture、`run_label` 或配置。
- [ ] 输出报告、台账和 HTML 的访问权限与源数据一致。
- [ ] 对外展示前检查 finding 证据是否含敏感属性预览或坐标。
- [ ] 使用 `verify` 核对报告与台账，并保留摘要和原始运行环境信息。
- [ ] 需要更强的来源证明时，另行签名或归档到受控审计系统。
- [ ] `serve` 只运行在可信本机，未做公网映射、反向代理或端口转发。
- [ ] 在共享机器上使用独立低权限账户，并保护台账文件权限。
- [ ] 需要保留历史时，不覆盖旧输出目录；台账新运行以新摘要追加。
